# Relay Wave 2 implementation report

Status: **partial implementation; Wave 2 acceptance is not claimed.** The five findings from the independent Sol Medium review and the single HIGH finding from the subsequent independent rereview are resolved for the delivered subset, with regressions and current schema/conformance evidence below. Independent acceptance is still pending. The starting checkpoint was `ce718db`. The interrupted agent's staged, unstaged and untracked changes were preserved; no reset, commit, push, publishing, remote creation, credentials or live provider calls were used. Sibling Blueprint, Sinal and oversight repositories were not edited.

## Delivered APIs and behavior

- `relay` exposes typed tool names, metadata, heterogeneous registries, schema-checked contextual handlers and a rich-content handler. `relay/tool` retains input/output/error codecs and admitted input/output schemas. `relay/content` defines text, image, audio, resource-link, embedded-resource, annotations and resource-content values.
- `relay/server` and `relay/protocol/v2026_07_28` provide a sans-I/O reducer for discovery, tool listing/calls, resource and template listing, resource reads, prompt listing/get, and completion. Per-request log-level metadata is validated; the obsolete `logging/setLevel` RPC is not admitted and no logging capability is advertised without an emitter. Resource, prompt and completion handlers retain their typed service callbacks. Application failures remain JSON-RPC result outcomes with `isError`; invalid arguments and protocol failures remain protocol errors.
- Pagination cursors are authenticated with a random per-server key and bind family and offset. This allows traversal across the Mist adapter's request-scoped runtimes while rejecting forged and cross-family cursors. Pure and HTTP integration tests cover traversal and rejection.
- `relay/transport/stdio` performs bounded newline framing and raw bounded reads, handles split UTF-8, serializes writes and returns typed I/O/startup/terminal errors. `relay/runtime` owns invocation workers, deadlines, cancellation, tombstones and Sinal lifecycle observations.
- `relay/transport/http` is a thin Mist adapter for POST, incremental bounded request bodies, JSON/media negotiation, MCP version/routing-header agreement, Host/Origin allow-lists, JSON responses, and live bounded request-scoped SSE event responses. Handler progress waits for runtime write completion; the live SSE writer waits for Mist's send acknowledgement and returns delivery failure to the runtime, which cancels active workers. The broker remembers the first failed delivery and rejects later frames without retrying a dead SSE actor. Idle probes detect disconnects. Local loopback tests cover a slow writer's bounded runtime mailbox and worker cancellation after a real peer disconnects during a progress burst.
- `relay/client` exposes an owner-bound Gun connection with discovery, checked raw JSON-RPC calls, paginated `tools/list`, codec-typed `tools/call`, typed resource reads, prompt gets and completion requests. Tool outcomes distinguish structured success, content-only success, tool failure, protocol failure, transport failure, cancellation and input-encoding failure. Content blocks decode as typed text, image, audio, resource-link and embedded-resource values, including annotations. The client enforces response size and total request deadlines.
- `relay_gun_ffi.erl` now owns only Gun connection, request, flow-control, cancellation and close behavior and returns bounded raw response bytes. Gleam performs JSON-RPC parsing/correlation; Blueprint parses structured values and tool declarations where exact numeric/schema values matter.
- [README.md](README.md) now describes the current subset and limitations instead of the obsolete Wave 1-only/deferred claims. [WAVE-2-PROGRESS.md](WAVE-2-PROGRESS.md) records progress and open scope.

## Friction and improvements

Implementation friction: the agy session ended with a quota failure despite an exit status that looked successful, so its completion claim was discarded and the existing staged, unstaged and untracked changes had to be re-audited. Nix checks require access to the host daemon, so they needed the authorized gate permissions. The specified Mist 6.0.3 reference is incompatible with the frozen Sinal stdlib constraint, so 6.0.2 was pinned after local dependency resolution. Automatic review rejected the proposed application-facing logging emitter because it would expose arbitrary handler-provided JSON to a connected client; the draft API was reverted rather than routed around that decision.

Improvements applied: a real two-POST list traversal exposed that request-scoped HTTP runtimes discarded in-memory cursors; cursor tokens now carry an authenticated server/family/offset binding. The Gun FFI was narrowed to transport-only work, with JSON-RPC and exact Blueprint parsing moved into Gleam. A single absolute request deadline replaces per-chunk timeout resets. Tests now cover cursor cross-family rejection, client timeout, exact structured numbers, rich server replies, typed client decoding for all five content block families, and typed resource/prompt/completion calls with routing-header agreement. The new schema gate checks actual delivered service results and malformed-field mutations. The progress reporter now waits for runtime write completion; live SSE delivery failure closes the runtime and kills the worker, and later broker deliveries fail without another dead-actor wait. A 128-value producer burst stayed within one queued owner message behind a held writer, and a loopback peer reset after the first SSE event caused worker exit within one second. Regressions also cover asynchronous broken stdout with idle stdin, duplicate-exchange capacity and continuation handling. The pinned official server suite is integrated and passing. The README's stale Wave 1 claims were replaced with the actual capability boundary.

Improvements proposed but not applied: add subscription/listen and dynamic registry notification routing, complete the typed client over stdio and add typed subscription methods, exercise owner/child death and process-count cleanup, add a local TLS peer, and add pinned TypeScript/Python typed-client interoperability fixtures. These remain Wave 2 continuation or later-wave work as listed in the ledger.
